# GPT-6.1 Sol の公式仕様と gateway 対応調査

- Date: 2026-09-30
- Status: 調査済み（Codex 経路での提供待ち）

## 一次資料

[OpenAI API changelog](https://developers.openai.com/api/docs/changelog) は 2026-09-29 に「Released GPT-6.1 Sol (`gpt-6.1-sol`) for complex coding and professional work at a lower cost than GPT-6 Astra」と記す。[モデル一覧](https://developers.openai.com/api/docs/models)の GPT-6.1 は Sol のみ。`gpt-6.1` 単独、`gpt-6.1-luna`、`gpt-6.1-astra` は同一覧で確認できない。公式モデルページは Sol 6 を「See GPT-6.1 Sol for the newer Sol model」と案内する一方、廃止日・廃止予告は記さない。

[GPT-6.1 Sol モデルページ](https://developers.openai.com/api/docs/models/gpt-6.1-sol)の「reasoning.effort supports low, medium (default), high, xhigh, and max. The none and minimal reasoning efforts are not supported.」により、`none` が利用可能な GPT-6 Sol からの移行では既存 effort を確認する必要がある。context window 1,050,000、最大入力 922,000、最大出力 128,000 tokens、知識 cutoff 2026-04-30。text/image 入力、text 出力。ツール利用には Responses API が必要で、Chat Completions はツールなしのみ対応。OpenAI は「Near-Astra performance for complex work at a lower cost」と主張し、coding・computer use・professional work を対象に挙げるが、当環境での品質比較は未実施。

[公式 Standard 価格表](https://developers.openai.com/api/docs/pricing)と[各モデルページ](https://developers.openai.com/api/docs/models/gpt-6-sol)の USD / 100 万 tokens。272K 入力以下の単価で、これを超えるリクエスト全体は input/cache 2 倍、output 1.5 倍。GPT-6.1 Sol は GPT-6 Sol と比べ cached input のみ半額。Batch/Flex は標準の半額、Fast は 2 倍、地域処理には別途 10% 加算がある。

| モデル | Input | Cached input | Cache write | Output |
|---|---:|---:|---:|---:|
| `gpt-6.1-sol` | $2 | $0.10 | $2.50 | $10 |
| `gpt-6-sol` | $2 | $0.20 | $2.50 | $10 |
| `gpt-6-luna` | $0.10 | $0.01 | $0.125 | $0.50 |

## 評判の検証範囲

2026-09-30 時点で第三者の検証可能な投稿・レビューを 3〜5 件確保できなかった。Reddit の公開検索は JSON を返さず、一般検索はアクセス制限を返した。公式の near-Astra という宣伝文を第三者による性能評価として扱わない。外部評価は未確認であり、同一条件の実務タスク比較が必要。

## gateway 実機観測と変更候補

- `GET http://127.0.0.1:11301/ns-personal/v1/models` の GPT-6 系は `gpt-6-astra`、`gpt-6-luna`、`gpt-6-sol` の 3 件。`gpt-6.1-sol` は無い。1 件だけ `POST /ns-personal/v1/responses` に `model: gpt-6.1-sol`、短い input、`max_output_tokens: 24` を送ると HTTP 404、`no route configured for model`。upstream へ到達した 404 と区別する必要がある。`ns-lab` は Claude 固定なので GPT 疎通には使わなかった。
- `crates/llm-gateway/src/discovery.rs` は Codex backend の `/models?client_version=...` を取得する。`crates/llm-gateway/src/router.rs` は発見済み catalog から経路を作る。現状の 404 は catalog に無いため gateway で経路が組まれないことまで示し、Codex provider 自体の GPT-6.1 提供可否は確定しない。discovery refresh 後の upstream 一覧を調べ、provider 公開と gateway 側の version/filter を切り分ける。
- `~/.config/llm-gateway/config-11301-unstable-new.toml` と `config-11302-stable.toml` の personal / bare / emrd alias `gpt-sol = "gpt-*-sol"` は `gpt-6.1-sol` にパターン上合致する。`resolve_alias` は発見済みの候補から作成時刻、同値なら ID の順に最新を選ぶので、発見された後に実 alias の解決先を確認する。設定の変更要否は現時点で確定しない。
- `crates/llm-gateway/src/preset/pricing.rs` は `gpt-6-sol` 行を持つが `gpt-6.1-sol` 行を持たない。両者は ID の prefix も異なるため新行（input $2、output $10、cache write $2.50、cache read $0.10）が必要。`gaps()` は catalog に現れた未価格モデルを警告するが、未発見の現時点では警告対象にならない。価格表を直す場合、当該モデルの価格・gap テストも合わせる。長文・Fast・地域別の単価は現在の固定 Standard 表では表現していないため、ここで勝手に適用しない。
- `scripts/keepalive-horizon-sim.py` の `MODEL_RATES` は Anthropic 系のみ。GPT-6.1 固有の追加対象ではない。
- agent 定義は `~/.local/share/repos/github.com/kawaz/claude-rules-personal/main/agents/` にある。`worker-sol-high.md` と `reviewer-sol-high.md` は `model: gpt-6-sol`、`reviewer-luna-xhigh.md` は `model: gpt-6-luna`。新 Sol は cached input が安い一方 `none` effort 不可・Codex 経路未発見であり、worker の変更は提供状況と実務品質比較を経て判断する。Luna に 6.1 variant は公式一覧で確認できず、Luna 定義の更新先はない。

調査中に gateway のコード、本番設定、agent 定義は変更していない。
