# events / usage の出力に denial の Reason を載せる

## 概要

events / usage の出力に denial の Reason を載せる (Reason::Paced が外から見えない)

## 背景

現状 denial の理由が `Reason::Paced` のような内部列挙のまま外部から確認できず、
events / usage 出力を見ても paced による denial なのか他の理由なのか判別できない。

## 受け入れ条件

- [ ] events / usage の出力に denial の Reason が含まれる
- [ ] Reason::Paced を含む各 denial 理由が外部から判別可能になる

## 現状の事実

- `crate::denial::Reason` は `Limited` / `Busy` / `Paced` の 3 値。`Paced` は
  DR-0019 で追加した「upstream に断られたのではなく gateway が自主的に控えた」
  ことを表す語
- Reason はどの出力スキーマにも載っていない。現状の露出は tracing ログのみ
  (router.rs の select 内 info! と gateway.rs の warn!)
- events (`/llm-gateway/events`, DR-0012) の `Event` は status code は持つが
  denial の理由欄を持たない
- usage (`/llm-gateway/usage`, DR-0007) も同様

## なぜ要るか

- pace_cap (DR-0019) で外した経路は upstream を叩いていないので、events だけ
  見ると「なぜこの経路が使われなかったのか」が分からない。429 として出るのは
  全滅時だけで、部分的に外れた場合は痕跡が残らない

## 作業の見積り

- events の Event スキーマに理由欄を足す変更なので、購読側 (ccmsg / 監視) との
  互換を見る必要がある。DR-0012 の追補か新規 DR の判断も含む

## なぜ今やらないか

- DR-0019 の実装スコープ外。スキーマ変更は購読側への影響があるため独立して
  判断すべきと整理した (統括承認済み 2026-08-16)

## 進捗

現状調査 (events/usage スキーマ・denial 流路・購読側互換) を並列 worker で開始。
調査後に DR-0012 追補 or 新規 DR の設計案を組んで kawaz 裁定へ載せる予定
